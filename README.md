# ClassTrack - Firebase Cloud Database Edition

## Overview

ClassTrack is a modern academic task management application built to demonstrate proficiency in cloud database integration, real-time data synchronization, and full-stack web development. As a software engineer, I developed this project to deepen my understanding of NoSQL databases, Firebase authentication, and building scalable applications that can serve multiple users simultaneously with real-time updates.

ClassTrack allows students and learners to organize their academic workload by creating courses, managing assignments, tracking completion progress, and visualizing statistics through an intuitive dashboard. The application integrates seamlessly with Google Firebase/Firestore, a cloud-native NoSQL database that provides automatic scaling, real-time data synchronization across devices, and built-in authentication mechanisms. Users can sign up with email and password, create and manage their own courses and assignments, mark work as complete, and receive instant updates across all connected devices through Firestore's real-time listeners.

The purpose of writing this software is to build practical experience with cloud databases while creating a tool that solves a real problem: helping learners stay organized and motivated by visualizing their academic progress. Unlike traditional localStorage-based applications, ClassTrack demonstrates how to architect a production-ready application with proper data isolation, security rules, and multi-user support.

## Cloud Database

ClassTrack uses **Google Firebase/Firestore**, a fully managed, cloud-hosted NoSQL database provided by Google Cloud. Firestore was chosen because it offers:

- **Real-time synchronization** — Data changes instantly sync across all connected clients without manual refresh
- **Automatic scaling** — Handles growth without manual server management
- **Built-in authentication** — Integrated user management and session handling
- **Security rules** — Fine-grained access control ensuring users only see their own data
- **Free tier** — Generous free tier sufficient for development and small-scale deployment

### Database Structure

ClassTrack uses three Firestore collections:

#### **1. users**
Stores user profiles and preferences.
- **Document ID**: Auto-generated by Firebase (matches user's UID)
- **Fields**:
  - `uid` (string) — Firebase Authentication UID
  - `email` (string) — User's email address
  - `displayName` (string) — User's full name
  - `createdAt` (timestamp) — Account creation date
  - `preferences` (object) — User settings (theme, notifications, etc.)

#### **2. courses**
Stores course information linked to users.
- **Document ID**: Auto-generated by Firestore
- **Fields**:
  - `userId` (string) — Foreign key linking to owner (acts like SQL foreign key)
  - `name` (string) — Course name (e.g., "Web Development")
  - `code` (string) — Course code (e.g., "CSE310")
  - `color` (string) — Hex color for UI styling
  - `credits` (number) — Credit hours
  - `semester` (string) — Semester taken (e.g., "Spring 2025")
  - `createdAt` (timestamp) — Course creation date

#### **3. assignments**
Stores assignment data with relationships to both users and courses.
- **Document ID**: Auto-generated by Firestore
- **Fields**:
  - `userId` (string) — Assignment owner (foreign key to users)
  - `courseId` (string) — Parent course (foreign key to courses)
  - `title` (string) — Assignment name
  - `dueDate` (string) — Due date in ISO format (YYYY-MM-DD)
  - `priority` (string) — Priority level (low, medium, high)
  - `points` (number) — Points or weight
  - `notes` (string) — Assignment details/requirements
  - `completed` (boolean) — Completion status
  - `createdAt` (timestamp) — Assignment creation date

### Key Relationships

- **User → Courses** — One-to-many (one user has many courses)
- **User → Assignments** — One-to-many (one user has many assignments)
- **Course → Assignments** — One-to-many (one course has many assignments)
- **Data Isolation** — Firestore Security Rules ensure users only access their own data

### Real-Time Features

The application uses Firestore's `.onSnapshot()` listeners to automatically update the UI whenever data changes:
- When a user creates a course, it appears instantly in the UI
- When marking an assignment complete in one browser tab, it updates in all other tabs in real-time
- When deleting a course, all related assignments are cascaded-deleted and removed from the UI
- Statistics (completion rate, total points, overdue tasks) recalculate automatically

## Development Environment

### Tools & Platform

- **IDE**: Visual Studio Code (VSCode) for code editing, debugging, and Git integration
- **Version Control**: Git & GitHub for source control and collaboration
- **Cloud Platform**: Google Firebase Console for database management, authentication, and security rules
- **Deployment**: Vercel for serverless frontend hosting with automatic CI/CD deployments from GitHub
- **Package Manager**: NPM for dependency management
- **Local Development Server**: Node.js development server with hot reload
- **Browser**: Chrome DevTools for debugging, network analysis, and real-time inspection

### Programming Languages & Libraries

- **Frontend Framework**: React 18.2.0
  - Component-based architecture for modularity and reusability
  - React Hooks (useState, useEffect) for state management and side effects
  - React Router 7.10.1 for client-side routing and navigation

- **Backend/Database**: Google Firebase SDK
  - `firebase` ^12.6.0 — Core Firebase library
  - Authentication module — Email/password sign-up and sign-in
  - Firestore module — Real-time NoSQL database operations (CRUD, queries, listeners)

- **Styling**: Custom CSS3
  - CSS variables for theming and consistent styling
  - Flexbox and CSS Grid for responsive layouts
  - Media queries for mobile responsiveness

- **Build Tools**: React Scripts 5.0.1 (Create React App)
  - Webpack for bundling and optimization
  - Babel for JSX and ES6+ transpilation
  - Development server with hot module reload
